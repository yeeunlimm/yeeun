# 서울 팝업 후보 분석기

현재 단계는 데이터를 안전하게 모으고 점검하는 Python 기반 초안입니다. 과거 시간대별 유동인구와 팝업 실적 정답 자료가 준비되기 전에는 ML 모델을 학습한 것처럼 결과를 만들지 않습니다.

## 모델링 실행

`popup_modeling.py`는 과거 실제값이 있을 때 시간대별 주변 유동/체류 인구를 모델링합니다. 같은 장소·요일·시간대 중앙값 기준선, Poisson 손실 회귀, 10·50·90 분위수 회귀 범위를 비교하고, 최대 24개 과거 완전 주를 시간순으로 고르게 뽑아 검증한 뒤 가장 최근 완전 주를 별도 최종 테스트로 남깁니다. 범위 회귀는 조건이 비슷한 과거 관측에서 하위 10%·중앙 50%·상위 90% 값을 추정합니다. Q10~Q90은 명목상 80% 폭이며, 롤링 검증 자료가 충분하면 과거 구간 밖 오차를 이용해 범위를 넓혀 최종 테스트에 적용합니다. 실제 포함률은 마지막 테스트에서 확인합니다. 시계열 특성 때문에 이 보정도 포함률 보장을 뜻하지 않습니다.

### 3년 자료를 받아 실제 학습하기

다음 명령 순서로 서울시 250m 격자 생활인구를 후보 권역별 시간대 합계로 만들고, 시간별 과거 예보모델 날씨 및 달력 변수를 붙인 뒤 전체 인구와 20~39세 인구 모델을 각각 학습·평가합니다. 기본 기간은 2023-09-21~2026-09-20입니다. 원본 월별 압축파일은 용량이 크며 `data/raw/` 아래에 보관됩니다.

```powershell
python -m pip install -r requirements.txt
python collect_seoul_population_history.py --start 2023-09-21 --end 2026-09-20
python collect_weather_history.py --start 2023-09-21 --end 2026-09-20
python prepare_population_training.py
python train_seoul_population.py
```

생활인구는 실제 팝업 입장객이나 매출이 아니라 장소 주변 격자에 머문 것으로 추정한 사람 수입니다. 기상 입력은 기상청 관측값 대신 과거 예보모델 아카이브를 사용합니다. 결과는 `outputs/modeling/three_year_run/`의 최근 완전 주 백테스트, 월별·달력별 비교, 변수 중요도와 전체 자료로 다시 학습한 모델 파일에 저장됩니다. 지역은 행정동 코드로 만든 넓은 후보 권역 대리값이며, 정확한 행사 주소나 주변 행사·대학·상권 정보는 아직 결합하지 않았습니다.

분위수 회귀는 평균 하나 대신 조건부 분포의 특정 분위수를 예측하는 방식입니다. scikit-learn의 표형 데이터용 히스토그램 그래디언트 부스팅 회귀 모델은 Poisson 손실과 quantile 손실을 지원합니다. [공식 모델 설명](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.HistGradientBoostingRegressor.html), [분위수 회귀 설명](https://scikit-learn.org/stable/modules/linear_model.html#quantile-regression)

기본 ML 최소 기준은 학습 200행·완전한 8주입니다. 모델 선택에는 최소 3개의 롤링 검증 주와 마지막 테스트 주가 별도로 필요하므로, 기본값으로는 대략 **12주 이상의 완전한 과거 자료**가 있어야 ML 선택을 검토할 수 있습니다. 이 기준은 품질 보증선이 아니라 데이터가 매우 적을 때 ML을 무리하게 쓰지 않기 위한 초기 보호 장치입니다. 롤링 검증에서 기준선이 가장 낮은 MAE를 내면 미래 후보도 기준선을 사용하고, ML 학습/검증이 부족하면 과거 관측 분위수로 시나리오만 표시합니다. 이런 시나리오 범위를 예측 구간이라고 부르지 않습니다.

먼저 PowerShell에서 프로젝트 폴더로 이동해 라이브러리를 설치합니다.

```powershell
python -m pip install -r requirements.txt
```

과거 테스트와 롤링 검증을 실행합니다.

```powershell
python popup_modeling.py backtest --history data/your_historical_footfall.csv
```

장소 후보·행사 날짜/시간·기상 예보·주변 변수로 범위를 산출하고 후보를 비교합니다. 실제 후보 주소와 예보 자료가 준비된 뒤 `data/templates/candidate_scenarios.csv`의 열 구조대로 시나리오 파일을 채웁니다.

`weather_status`는 `pass/통과`, `caution/주의`, `stop/제외/위험/운영불가` 중 하나로 기록합니다. 이 코드는 `stop` 계열을 야외 후보에서 제외하고 `caution`은 주의 후보로 남깁니다. 강수량·미세먼지의 통과 기준은 클라이언트의 운영 기준이 아직 정해지지 않아 임의 설정하지 않았습니다.

```powershell
python popup_modeling.py forecast --history data/your_historical_footfall.csv --scenarios data/your_candidate_scenarios.csv
```

기본 산출물은 `outputs/modeling/` 아래의 Markdown/JSON 백테스트 요약, 테스트 주별 예측 CSV, 후보별 예측 CSV입니다. `MAE`는 시간대별 평균 인원 차이, `WAPE`는 실제 전체 합계 대비 오차, `coverage_80`은 테스트 실제값이 Q10~Q90 사이에 들어온 비율입니다. 낮은 MAE와 구간 포함률은 함께 보고, 구간 폭도 확인합니다. 과거 자료가 적으면 미래 후보는 기준선/관측 분포 시나리오로 출력합니다. 입력 행이 전혀 없으면 인원 예측은 만들지 않습니다. 빈 템플릿이나 문화행사 목록은 유동인구 정답값이 아니므로 학습 파일로 사용하지 않습니다.

## 과거 유동인구 자료 해석

- 서울 생활인구 250m 격자 자료는 시간별 통신자료 기반 **추정 체류 인구**입니다. 타깃 그리드에 대한 과거 시계열을 만들고 20·30대 인원 구성이 확인되면 연령 추정에 보조로 쓸 수 있지만, 거리의 실제 통행량이나 팝업 방문객과 동일하지 않습니다. 공식 안내상 자료는 4일 뒤 공개되며, 실제 인구와 차이가 날 수 있는 통계 추정치입니다. [서울 생활인구 설명 및 다운로드](https://data.seoul.go.kr/dataVisual/seoul/seoulLivingPopulation.do)
- S-DoT 유동인구 자료는 서울 내 센서 100곳의 10분 단위 관측이며 Wi-Fi/CCTV 기반 근삿값이라 실제 인원 수와 차이가 날 수 있습니다. 후보 장소에 가까운 센서가 있는지 먼저 확인해야 합니다. [S-DoT 데이터 설명·파일 목록](https://data.seoul.go.kr/dataList/OA-15964/S/1/datasetView.do)
- `서울특별시_상권분석서비스(길단위인구_행정동)` 파일은 행정동 단위 분기 자료입니다. 연령·상권 배경 비교에는 쓸 수 있지만, 시간대별 행이 없으므로 시간대 모델의 정답 레이블로 쓰면 안 됩니다. [파일 데이터 안내](https://www.data.go.kr/data/15147228/fileData.do)

기상 변수는 해당 과거 날짜의 **실제 관측 날씨가 아니라 행사 전에 알 수 있었던 예보**를 넣어야 실제 운영 시점과 맞는 검증이 됩니다. 예보 발표 시각부터 행사까지의 간격(`forecast_lead_hours`)도 기록하고, 미래 시나리오와 학습자료의 예보 선행시간을 최대한 맞춥니다. 예보 이력 자료가 없으면 이 변수는 비워 두고 달력·장소 같은 확보 가능한 변수로 모델링합니다. 실제 관측 날씨를 미래 시점 예측 입력으로 쓰면 누수(예측 시점에는 몰랐을 정보를 학습에 사용)입니다.

실제 행사 방문객을 예측하려면 팝업 입구 집계가 별도의 정답 자료로 필요합니다. 이 모델이 우선 예측하는 값은 입력 파일의 `footfall_total` 정의에 따른 주변 유동/체류 인구입니다. 모델 예측 범위와 과거 검증의 포함률이 확인되기 전에 고객 보고서에 검증된 예측 구간처럼 표현하지 않습니다.

## 필요한 데이터

### 지금 사용 가능한 자료

- `서울시 문화행사 정보.csv`: 행사명·기간·장소·자치구·좌표·상세 URL이 있어 주변 행사와 팝업 이력을 찾는 데 사용합니다. 팝업 전수 목록이나 방문객/매출 자료는 아닙니다. 원본 파일을 저장소에 복사하지 말고 경로를 실행 옵션으로 전달합니다.
- 서울 실시간 도시데이터: 지원하는 주요 핫스팟의 실시간 인구 범위, 성별/연령 비율, 갱신 시각. 과거 시간대 기록은 이 API의 현재 응답만으로 소급할 수 없습니다.
- 기상청 중기육상예보: 서울·경기 권역의 먼 날짜 날씨/강수 가능성. 야외 위험의 사전 참고용입니다.

### 실제 유동인구 모델을 만들 때 필요한 과거 자료

최소 한 행이 `장소 × 날짜 × 시간대`를 나타내는 CSV가 필요합니다. 가능한 한 최근 1년 이상, 여러 장소와 계절의 관측치를 사용합니다. `data/templates/historical_footfall.csv`에 기대하는 열을 적었습니다.

- 타깃: 같은 공간 범위·같은 시간대에 측정한 실제 보행/체류 인원
- 예측 입력 후보: 날짜/요일/휴일, 날씨, 장소 ID, 20대/30대 구성, 교통 접근성, 확인된 주변 행사
- 선택 자료: 과거 팝업 방문객 수/POS 집계. 이것이 있어야 팝업 입장객이나 매출을 직접 예측하는 별도 모델을 만들 수 있습니다.

행사 성과 기록 양식은 `data/templates/popup_outcomes.csv`에 있습니다. 행사 종료 후 방문객 카운터와 POS의 시간대별 방문 수·구매 건수·순매출·판매량을 같은 시간 단위로 기록합니다. 개인정보는 저장하지 않습니다.

## 필요한 API와 권한

1. **서울시 실시간 도시데이터**: 사용자가 발급한 서울 열린데이터광장 키. `citydata` 이용 신청/권한이 있어야 하며, 조회 가능한 주요 핫스팟만 사용할 수 있습니다.
2. **기상청 단기예보 + 중기예보**: 공공데이터포털 서비스키와 각 서비스 활용 신청/승인. 짧은 기간은 격자별 단기예보, 더 먼 날짜는 중기육상예보를 사용합니다. 같은 서비스키를 쓸 수 있는지는 포털의 서비스별 승인 상태로 확인합니다.
3. **서울시 상권분석 유동인구**: 도로/건물 단위의 과거 시간대·요일·연령 자료를 우선 확보합니다. 정확한 공간/시간 해상도와 CSV 다운로드/오픈API 사용 가능 여부는 후보 주소를 정한 뒤 확인합니다.

`.env.example`을 `.env`로 복사한 뒤 새로 발급한 키를 `.env`에 넣으면 수집기가 자동으로 읽습니다. `.env`는 `.gitignore`에 등록되어 Git에 올라가지 않습니다. 기존에 채팅으로 보낸 키는 재발급하는 편이 안전합니다. 키를 코드에 직접 적거나 저장소에 커밋하지 마세요.

```powershell
Copy-Item .env.example .env
# 메모장 등으로 .env를 열어 두 키의 값을 입력합니다.
notepad .env
```

유튜브 댓글 분석은 브랜드/상품군 또는 후보 영상 범위가 정해진 뒤 선택합니다. 핵심 장소·날짜 분석에는 댓글이 필요하지 않습니다. 댓글 표본을 직접 제공하면 수집 API 없이 분석할 수 있고, 여러 영상에서 재현 가능하게 수집하려면 YouTube Data API 키가 필요하므로 그때 요청합니다. 지금은 키를 요청하지 않습니다. 대기질은 서울 실시간 도시데이터의 측정값을 쓸 수 없는 후보가 정해진 경우에만 별도 AirKorea API를 검토합니다.

## 실행

먼저 PowerShell에서 이 프로젝트 폴더로 이동한 다음 아래 명령을 실행합니다.

```powershell
python seoul_popup_pipeline.py inspect-events --csv "C:\Users\Administrator\Downloads\서울시 문화행사 정보.csv" --start 2026-10-05 --end 2026-10-11
```

응답은 `data/raw/` 아래에 수집 시각과 장소/예보 기준을 붙여 저장합니다. 키는 파일이나 로그에 저장하지 않습니다. 격자 좌표와 예보 발표시각은 실제 행사 주소와 조회 시각을 확인한 뒤 사용합니다.

## 현재 필요한 사용자 자료

- 서울 실시간 API에서 지원되는 장소 이름 목록(또는 응답 확인 후 고를 수 있도록 우선 후보 권역)
- 서울시 상권분석서비스에서 받은 과거 도로/건물 유동인구 CSV. 특히 날짜·요일·시간대·20대/30대 정보가 있는 자료
- 후보 장소가 정해지면 정확한 주소, 운영 가능일/시간, 대관비, 수용량, 우천 대안/실내 여부
- 과거 팝업의 시간별 실제 방문객 수/매출/POS 집계가 있다면 별도 파일 (없으면 팝업 성과 예측 ML은 학습 불가)

브랜드/제품은 아직 없어도 데이터 수집 코드와 공개 유동인구 기반 장소 후보 탐색은 시작할 수 있습니다. 온라인 소비자 반응 분석은 브랜드/상품 정보가 생기기 전까지 보류합니다.
